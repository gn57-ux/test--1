# Feature 1: scene-foundation — 深海场景基础设施

## 概述
搭建项目技术基础：Vite + Three.js 场景框架、HTML/Canvas 分层架构、基础渲染管线（相机/渲染器/灯光/雾/粒子/气泡/Bloom 后期）、WebGL 兼容性降级、加载状态、响应式与设备性能适配、reduced-motion 基础设施、场景资源释放。是其余所有 Feature 的运行时地基。

## 版本
v1 - 初始版本

## 用户故事
- 作为访客，我打开页面时能看到加载状态提示，而不是空白或卡死页面。
- 作为使用不支持 WebGL 浏览器的访客，我能看到有意义的静态降级内容而非黑屏。
- 作为移动端访客，我能在性能受限设备上依然流畅浏览页面。
- 作为启用"减少动态效果"系统设置的访客，页面动画强度会相应降低。

## 功能需求
- F-001：系统应创建完整 Three.js 场景，包含相机、渲染器、灯光、雾效、漂浮颗粒与上升气泡粒子系统。（对应 PRD F-001、5.3）
- F-002：系统应使用 EffectComposer 实现 Bloom 等后期处理效果，效果强度保持克制，不影响文字可读性。（对应 PRD 5.3、8）
- F-003：HTML UI 层与 Three.js Canvas 层必须分层管理，重要文字必须使用 HTML 渲染。（对应 PRD 8、7.可访问性）
- F-004：3D 资源加载期间应显示简洁的加载状态。（对应 PRD F-008）
- F-005：不支持 WebGL 的浏览器应显示静态背景、项目标题和说明文字，而非黑屏或报错。（对应 PRD 7.兼容性）
- F-006：页面应适配桌面端、平板和手机；移动端可降低粒子数量、渲染精度（devicePixelRatio）和后期效果。（对应 PRD F-007）
- F-007：系统应提供全局"减少动态效果"状态（基于 prefers-reduced-motion，可选叠加页面内开关），供其他 Feature 读取以降低动画强度。（对应 PRD 7.可访问性）
- F-008：离开页面或销毁场景时，应释放几何体、材质、纹理和事件监听器。（对应 PRD 7.性能）

## 非功能需求
- 页面首次进入时应尽快显示加载界面。
- 桌面端交互保持流畅（无明显掉帧）。
- 移动端根据设备能力降低像素比和粒子数量。
- 兼容近期版本 Chrome / Edge / Safari / Firefox / iOS Safari / Android Chrome。

## 验收标准
- AC-001：打开页面后能看到加载状态。（对应 PRD AC-001 部分）
- AC-002：不支持 WebGL 的浏览器显示静态背景、标题和说明文字，不出现黑屏。（对应 PRD AC-010 相关、7.兼容性）
- AC-003：移动端不会因为粒子或后期效果出现明显卡死。（对应 PRD AC-009）
- AC-004：浏览器控制台不存在持续性错误或资源泄漏警告。（对应 PRD AC-012 部分）
- AC-005：系统启用"减少动态效果"时，暴露的全局状态可被其他模块正确读取。（对应 PRD AC-011 基础设施部分）

## 依赖
无（基础设施 Feature，其余 Feature 依赖本 Feature）。

## 已确认决定
- 项目使用 Vite + TypeScript + Three.js，无需 React（PRD 第 8 节）。
- 展品 3D 实现方式（基础几何体 vs GLTF 模型）由 Feature 3 的 design.md 决定，本 Feature 只负责底层渲染管线，不限定具体展品资源格式。
