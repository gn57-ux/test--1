# 《深海失物博物馆》产品需求文档

## 1. 项目概述

《深海失物博物馆》是一个使用 Three.js 制作的沉浸式 3D 单页网站。

用户通过滚动页面逐渐潜入深海，依次发现五件被封存在透明气泡中的“失物”。每件物品都承载一段关于遗憾、成长或告别的短故事。

页面不提供传统商品或业务功能，核心目标是通过 3D 场景、滚动叙事和诗意文案，形成具有视觉冲击力和情绪感染力的数字展览。

## 2. 产品目标

- 制作一个具有完整叙事过程的 Three.js 3D 静态页面。

- 展示 Three.js 场景、粒子、灯光、模型和后期处理能力。

- 让用户在 2–3 分钟内完成一次从海面到海沟的沉浸式体验。

- 桌面端呈现完整视觉效果，移动端保持核心体验。

- 不依赖后端服务，能够部署到任意静态托管平台。

## 3. 目标用户

- 喜欢数字艺术、视觉实验和沉浸式网页的用户。

- Three.js、WebGL 或创意前端作品的浏览者。

- 作品集、创意比赛或黑客松的评审人员。

## 4. 核心体验

### 4.1 开场：进入深海

页面初始为接近黑色的深蓝背景。

中央显示：

> 深海失物博物馆  
> 向下滚动，寻找那些没有真正消失的东西

用户开始滚动后：

- 标题逐渐淡出。

- 镜头穿过海面进入水下。

- 环境颜色由浅蓝逐渐过渡到深蓝黑。

- 水中出现缓慢漂浮的颗粒、气泡和光束。

- 页面右侧显示简洁的下潜深度。

### 4.2 展品浏览

页面包含五件展品：

#### 展品一：纸飞机

名称：没有寄出的远方

故事：

> 它曾经写满目的地，  
> 最后却一直停在出发之前。

视觉表现：

- 白色纸飞机缓慢漂浮。

- 周围气泡带有柔和的冷白色光晕。

#### 展品二：旧磁带

名称：没有播放完的夏天

故事：

> 磁带停在某一首歌的中间，  
> 像那个没有正式说完的告别。

视觉表现：

- 黑色磁带缓慢旋转。

- 标签使用褪色橙色。

- 靠近时出现轻微磁带转动效果。

#### 展品三：旧钥匙

名称：再也打不开的门

故事：

> 钥匙还记得锁的形状，  
> 只是那扇门已经不在原来的地方。

视觉表现：

- 金属钥匙带有轻微锈迹。

- 使用暖黄色轮廓光，与深蓝环境形成对比。

#### 展品四：拍立得照片

名称：被时间曝光的人

故事：

> 照片留下了那一天，  
> 却没有留下后来发生的事。

视觉表现：

- 拍立得照片在水中轻微摆动。

- 图片区域模糊，只保留人物轮廓。

#### 展品五：微型宇航员

名称：没有抵达的星球

故事：

> 他一直向上看，  
> 却被留在了世界最深的地方。

视觉表现：

- 白色宇航员模型悬浮在最终展区。

- 面罩反射远处蓝色光源。

- 周围出现少量星点般的发光粒子。

### 4.3 展品交互

桌面端：

- 鼠标移动产生轻微镜头视差。

- 鼠标经过展品时，展品高亮并减慢旋转。

- 光标变为可交互状态。

- 点击展品后显示对应故事卡片。

移动端：

- 点击展品打开故事卡片。

- 再次点击空白区域或关闭按钮收起卡片。

- 不依赖 Hover 操作。

故事卡片要求：

- 使用半透明深色玻璃效果。

- 显示展品编号、名称和故事。

- 不遮挡整个 3D 场景。

- 支持关闭。

- 同一时间只能打开一张卡片。

### 4.4 结尾：海沟展厅

用户滚动到页面底部后进入最深区域。

场景逐渐变暗，远处出现发光水母。水母或发光粒子围绕最终文案缓慢移动：

> 有些东西没有消失，  
> 只是沉到了记忆更深的地方。

底部提供：

- “返回海面”按钮。

- 项目名称和简单制作说明。

- GitHub 或作品集链接的预留位置。

点击“返回海面”后，页面平滑滚动至顶部，镜头回到初始位置。

## 5. 视觉设计

### 5.1 色彩

- 主背景：深海蓝黑 `#020711`

- 次级背景：深蓝 `#061A2D`

- 主发光色：青蓝 `#45D6E8`

- 辅助发光色：冷白 `#DDF7FF`

- 情绪点缀色：旧橙色 `#D98B4A`

- 正文颜色：浅灰蓝 `#C6D7E2`

### 5.2 字体

- 中文使用清晰、偏现代的无衬线字体。

- 展品标题可使用较细字重。

- 数字、深度和展品编号使用等宽字体。

- 页面文字不使用过多粗体。

### 5.3 3D 环境

场景至少包含：

- 深海雾效果。

- 漂浮颗粒。

- 上升气泡。

- 柔和环境光。

- 展品局部光源。

- 随深度变化的背景颜色。

- 适度 Bloom 辉光效果。

视觉效果应保持克制，避免大量强光造成文字难以阅读。

## 6. 功能需求

### F-001：3D 深海场景

系统应创建完整的 Three.js 场景，包括相机、渲染器、灯光、雾、粒子和气泡。

### F-002：滚动驱动镜头

页面滚动位置应控制镜头下潜深度，并依次经过五个展品区域。

镜头运动需要平滑，不能直接跳跃。

### F-003：五件可交互展品

系统应显示五件不同的 3D 展品。

展品可以使用基础几何体组合或本地 GLTF 模型，但不得依赖运行时外部模型服务。

### F-004：展品故事卡片

点击展品后应显示对应故事卡片。

故事内容由本地数据文件管理，展示逻辑不应硬编码在多个组件中。

### F-005：视觉反馈

展品需要具备悬停或点击高亮、缓慢旋转、浮动以及局部光效。

### F-006：结尾展区

页面底部应显示最终文案、发光水母或粒子效果，以及“返回海面”按钮。

### F-007：响应式适配

页面应支持桌面端、平板和手机。

移动端可以降低粒子数量、渲染精度和后期效果，但不能删除展品浏览与故事功能。

### F-008：加载与异常处理

3D 资源加载期间应显示简洁的加载状态。

模型或纹理加载失败时，页面应使用基础几何体占位，不能保持黑屏或阻塞整个页面。

## 7. 非功能需求

### 性能

- 页面首次进入时应尽快显示加载界面。

- 桌面端交互应保持流畅。

- 移动端应根据设备能力降低像素比和粒子数量。

- 离开页面或销毁场景时，应释放几何体、材质、纹理和事件监听器。

### 兼容性

支持近期版本的：

- Chrome

- Edge

- Safari

- Firefox

- iOS Safari

- Android Chrome

不支持 WebGL 时，应显示静态背景、项目标题和说明文字。

### 可访问性

- 故事卡片可通过键盘关闭。

- 交互元素具有明确的可访问名称。

- 用户启用“减少动态效果”时，降低镜头、粒子和展品动画强度。

- 重要文字必须使用 HTML 渲染，不能只存在于 Canvas 中。

### 安全与隐私

- 不采集用户数据。

- 不使用登录、Cookie 或分析服务。

- 不在代码中包含密钥或个人信息。

- 所有资源使用本地文件或明确允许跨域访问的静态资源。

## 8. 技术约束

- 使用 Three.js。

- 使用 Vite 作为开发与构建工具。

- 页面为单页静态网站。

- 不使用后端或数据库。

- 展品信息保存在本地 JSON 或 TypeScript 数据文件中。

- HTML UI 与 Three.js Canvas 分层管理。

- 允许使用 GSAP 或自定义插值实现滚动动画。

- Bloom 等效果使用 Three.js EffectComposer。

- 不强制使用 React，优先选择最轻量且适合当前项目的实现方式。

## 9. 验收标准

- AC-001：打开页面后能看到加载状态和开场标题。

- AC-002：滚动页面时镜头能够平滑下潜。

- AC-003：用户能够依次看到五件不同展品。

- AC-004：每件展品均可打开对应故事卡片。

- AC-005：桌面端具有鼠标视差和悬停反馈。

- AC-006：移动端可通过点击完成全部展品交互。

- AC-007：滚动到底部后显示最终文案和水母或粒子效果。

- AC-008：“返回海面”能够将页面与镜头恢复至开场位置。

- AC-009：移动端不会因为粒子或后期效果出现明显卡死。

- AC-010：资源加载失败时显示替代内容，不出现永久黑屏。

- AC-011：减少动态效果模式能够正常工作。

- AC-012：浏览器控制台不存在持续性错误或资源泄漏警告。

## 10. 本期不包含

- 用户账号系统。

- 后端接口和数据库。

- 用户上传自己的“失物”。

- 在线编辑展品。

- 多人互动。

- VR/AR 模式。

- 自动播放背景音乐。

- METATRON 或外部安全扫描。

- 数据分析与行为追踪。

## 11. 项目完成标准

用户能够从开场进入深海，通过滚动依次探索五件失物，查看每件展品的故事，最终到达海沟展厅并返回海面。

整个过程应形成完整、连贯且具有情绪表达的 3D 叙事体验。
